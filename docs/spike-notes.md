## 発見した問題

### ウィジェット上の横スワイプがタップとして扱われる

指がウィジェットの枠内に収まったまま横にスワイプすると、`AppWidgetHostView` はタップと判定して提供元のアプリを開く。Duolingo と GitHub の両方で再現した。ページ送りのスワイプでアプリが開いてしまうので、ホームとしては致命的。

対策として、Compose 側の `pointerInput` の Initial パスで動きを監視する。タッチスロップを超えた時点で横方向が優勢なら、以降のイベントを消費する。消費すると相互運用層が View に `ACTION_CANCEL` を送り、提供元は開かない。縦方向はウィジェット内部のスクロールのためにそのまま渡す。修正後は両ウィジェットで、横スワイプでは開かず、タップでは開くことを確認した。

`AndroidView` を包む Compose 側の実装で足りたので、View ラッパーへの切り替えは不要と判断する。縦スクロールするリスト型ウィジェットとの干渉は、該当するウィジェットが無く未検証。

### Norton 360 がインストールのたびに警告する

デバッグ版をインストール・更新するたびに、Norton 360 が「疑わしいアプリ」として警告を出す。検出 ID は 9a7cafc7b207。ストア外の署名、ホームとして振る舞えること、通知へのアクセスを要求できることの組み合わせが原因と見ている。検証中は Norton の除外設定を推奨する。警告の画面が前面に出るとタップ操作を吸われるので、自動操作の前に確認が要る。

## 通知バッジ

許可直後のアクティブ通知は 142 件で、集計結果は 24 アプリ・97 件だった。差の多くは常駐通知の除外と、まとめ通知の除外による。

X（com.twitter.android）は通知記録 8 件に対してバッジ 6。グループは Android 17 が付ける `Aggregate_AlertingSection` と `Aggregate_SilentSection` の2つに分かれていた。この差の2件は OS のまとめ通知を除外した結果と推定する。個々の記録のフラグまでは確認していない。

Android 17 では、アプリが自分でグループを付けない通知も OS がセクション単位でまとめる。子通知があるまとめ通知を数えない規則は、この場合にも効いている。

## 残りの検証

1. Discord と Gmail に通知が来たときの件数と、既読・削除でバッジが減ること。
2. 通知へのアクセスの撤回と再許可。撤回中に「未許可」と表示され、古い数が残らないこと。
3. 端末の再起動後に、ウィジェットと通知の集計が戻ること。
4. ウィジェットの長押しメニューから削除し、ホスト側の ID が解放されること。取消時と同じ処理経路なので優先度は低い。
5. 提供元アプリの更新・削除時の挙動。
6. 設定画面から元のホームアプリへ戻す操作。
