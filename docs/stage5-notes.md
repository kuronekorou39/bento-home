## 発見した問題

### 待機中も毎フレーム描き直していた

ホームを表示しているだけで、1コア換算で約55%の CPU を使い、毎秒約60フレーム描いていた。原因は2つあった。

1. ページャーに渡すページ数とキーのラムダが、再コンポーズのたびに作り直されていた。ページャーがそれを状態として書き換え、ページ数を読んでいるホーム画面がまた再コンポーズされる、という繰り返しになっていた。段階2から起きていたと見ている。ページの一覧とラムダを `remember` で固定して解消した。
2. Duolingo ウィジェットが、提供元の作りでアニメーションを続けている。外すと描画は止まった。ホーム側では、見えていないページのウィジェットと、アプリ一覧の下になっているウィジェットの View を非表示にし、アニメーションを止めるようにした。

| 状態 | 描画（4秒） | CPU（10秒） |
|---|---|---|
| 修正前・1ページ目 | 約250フレーム | 5.5 コア秒 |
| 修正後・1ページ目（Duolingo が見えている） | 約250フレーム | 2.9 コア秒 |
| 修正後・2ページ目 | 0 フレーム | 0.01 コア秒 |
| 修正後・アプリ一覧 | 0 フレーム | — |

Duolingo が見えている間の負荷は提供元のアニメーションによるもの。気になる場合は、Duolingo を2ページ目以降に置くと、ホームの最初のページでは描画が止まる。他のアプリを使っている間と画面が消えている間は、ホームは描画しない。

### 大きな文字でアプリ一覧の並び順の切り替えが崩れる

文字サイズを 1.6 倍にすると、「最近開いた順」が折り返し、件数の表示が縦に潰れた。並び順の行を横にスクロールできるようにして解消した。ホームのアイコンの大きさの計算も、ラベルの高さを文字の倍率込みで見積もるようにした。

## メモリ

ホーム表示中の PSS は約186MB（うちグラフィックス約80MB、Java ヒープ約35MB）。アイコンのキャッシュはメモリクラスの 1/8 が上限。

## 気づいた点

- 再インストールの直後にホームキーを押すと、ホームアプリの選択画面が出る。段階3・4でも同じだった。
- 再インストール直後は通知サービスの再接続まで数秒かかり、その間はバッジが出ない。
- 書き出したバックアップ `bento-home-2026-10-26.json` は端末のダウンロードに残してある。
