# システムモニター・透明性のページ・ウィジェットの負荷計測

記録日: 2026-10-26（日本時間）  
端末: Pixel 9a / Android 17（CP3A.260905.009）  
背景と方針は `docs/launcher-analysis.md` §1・§4。本人の端末で使う前提で、取れる情報を最大にする。

## 1. 権限の段階

Android 17 は、他のアプリのプロセスをアプリから見せない。adb のシェル権限なら見えるので、Bento 自身の計測用プロセスをシェル権限で動かす。外部アプリ（Shizuku など）は使わない。実機で次のとおり確かめた（シェル権限の列は、一時的に Shizuku で起動して確かめた結果。Shizuku はその後削除した）。

| 情報 | 権限なし | adb で付与（DUMP・使用状況） | シェル権限の計測用プロセス |
|---|---|---|---|
| 端末全体のメモリ・通信量・CPU 周波数 | 読める | 読める | 読める |
| 電池の電流 | 読める（BatteryManager） | 読める | 読める |
| 発熱の状態・余裕 | 読める（PowerManager） | 読める | 読める |
| 温度センサー（表面・CPU・電池） | 電池だけ | 読める（`dumpsys thermalservice`） | 読める |
| アプリごとの使用時間・通信量・容量 | 読めない | 読める | 読める（appops で付与） |
| 端末全体の CPU 使用率（`/proc/stat`） | 拒否 | 拒否 | 読める |
| 全プロセスの CPU 時間・メモリ（RSS） | 拒否 | 拒否 | 読める |
| `dumpsys meminfo`・`dumpsys cpuinfo` | 拒否 | サービスが見つからない（SELinux） | 読める（1回約5秒と重いので使わない） |
| プロセスごとの PSS（`smaps_rollup`） | 拒否 | 拒否 | 拒否 |

- adb で付与した DUMP は、`dumpsys thermalservice` と `dumpsys netstats` には効くが、プロセスの情報には効かない。
- adb での付与は再起動後も残る。計測用プロセスは再起動のたびに PC の adb から起動し直す（`docs/operations.md`）。
- 起動は `app_process` で Bento の APK の `Starter` を動かし、窓口（Binder）を Bento の ContentProvider（`PrivilegedReceiver`）に渡す。Shizuku と同じ方式を Bento 自身で行う（§2）。
- 計測用プロセスが動いているときは、モニター画面から使用状況へのアクセスと DUMP をまとめて付与できる（`appops set` と `pm grant` をシェル権限で実行）。

## 2. 構成（`monitor/`）

| 部品 | 役割 |
|---|---|
| `priv/PrivilegedService` + `IPrivilegedService.aidl` | シェル権限で起動する計測用プロセス。`/proc/stat`、全プロセスの `/proc/<pid>/stat`、`/proc/net/dev`、電池の電流を読み、行形式のテキストで返す。コマンド実行（`exec`）も持つ |
| `priv/Starter` | 計測用プロセスの入口（`app_process` から起動）。Bento の uid を聞いてから窓口を渡し、標準入出力を閉じて待機する。Bento のプロセスが終わったら渡し直し、APK が消えたら（更新・削除）終了する。ContentProvider は隠し API（`IActivityManager.getContentProviderExternal`）をリフレクションで呼ぶ |
| `priv/PrivilegedProtocol` | `Starter` と Bento の間の取り決め（authority・メソッド名・起動コマンド） |
| `PrivilegedReceiver` | 窓口を受け取る ContentProvider。INTERACT_ACROSS_USERS_FULL を要求し、呼び出し元がシェルか root かも確かめる |
| `PrivilegedBridge` | 計測用プロセスとの接続。差し込み口は `connect(binder)` の1か所。プロセスが終わると自動で切り離す。別の計測用プロセスが来たら古いほうを終了させる |
| `ProcSnapshot`・`ProcMath` | 行形式の解析と、2時点の差からの CPU 使用率の計算（単体テスト対象） |
| `Temperatures` | `dumpsys thermalservice` の解析。HAL の現在値を優先し、無いものはキャッシュから補う（単体テスト対象） |
| `MonitorRepository` | 定期的に読み、直近30分の時系列をメモリに持つ |
| `AppStats` | 使用状況へのアクセスで読む、今日の使用時間・通信量と、アプリごとの容量 |
| `AppRows` | プロセス・uid・パッケージをアプリ単位にまとめる（単体テスト対象） |
| `SelfMetrics` | Bento 自身の CPU 時間と、ホームの描画フレーム数（`OnFrameMetricsAvailableListener`） |
| `WidgetMetrics` | ウィジェットごとの更新回数と計測結果。`AppWidgetHost.onCreateView` で更新を数える View に差し替える |
| `MonitorActivity`・`MonitorUi` | 画面（概要・アプリ・棚卸し・ウィジェット・Bento の5タブ）と、タブ共通の見出し・面 |
| `OverviewTab`・`MetricChart` | 概要。値ごとの数値カード（小さいグラフ付き）を並べ、押したカードの大きい折れ線グラフを下に出す |
| `Inventory`・`InventoryTab`・`InventoryParsing` | 棚卸し（docs/stage6-notes.md §8）。電池と権限の使用は計測用プロセスの出力を読む（単体テスト対象） |

### 読み取りの間隔

- モニター画面を表示している間: 2秒ごと。シェル権限のプロセスで全プロセスも読む。温度は6秒ごと。
- ホームを表示している間: 10秒ごとに軽い値だけ（メモリ・通信量・電池・発熱・CPU 周波数）。シェル権限のプロセスは使わない。
- どちらも表示していない間は読まない。グラフの値はメモリ上だけで、Bento を終了すると消える。

### 値の意味

- CPU 使用率は全コアの合計を 100% とする（Windows のタスクマネージャーと同じ）。ウィジェットの負荷だけは「1コアあたり」で表す。
- アプリのメモリは各プロセスの RSS の合計。共有部分を重ねて数えるので実際より大きい。PSS はシェル権限でも読めないため使わない。
- uid がアプリに割り当てられていない隔離プロセス（ブラウザーのサンドボックスなど）は、プロセス名からアプリを推測する。計測用プロセスは「Bento の計測用プロセス」と表示する。

## 3. ウィジェットの負荷計測

ウィジェットの描画は Bento のプロセスで行うので、ウィジェットを表示したときと隠したときの、Bento の CPU 時間と描画フレーム数の差がそのウィジェットの負荷になる。

- ホームでウィジェットを長押し →「負荷を測る」。表示と非表示を 2秒ずつ3往復し（切り替え後 0.5秒待つ）、それぞれ合計して比べる。約15秒。
- 1回ずつ5秒測る方式では、GitHub（静的）が CPU 6.2% と出た。隣の Duolingo のアニメーションの揺らぎが混ざるため。交互に繰り返す方式で 3.3% に下がった。
- 判定: CPU 8% 以上（1コアあたり）か、描画が毎秒5回以上なら「重め」として、後ろのページへ移すことを勧める。CPU の閾値は上の誤差を超える値にした。
- 計測中は操作を受け付けない。計測中の表示に回転アイコンを使うと、両方の区間で毎フレーム描画されて描画数の差が0になったため、1秒ごとに変わる残り秒数だけにした。
- 同時に、View の木から動き続ける部品（実行中のアニメーション画像、回転する読み込み表示、自動で切り替わる表示、秒を表示する時計）を探して表示する。
- 計測中にホームを離れたら結果を捨てる。

### 実機の結果

| ウィジェット | CPU（1コアあたり） | 描画 | 動き続ける部品 | 判定 |
|---|---|---|---|---|
| Duolingo | 約23〜26% | 毎秒59回 | 回転する読み込み表示 | 重め |
| GitHub | 約3%（誤差の範囲） | 毎秒0回 | なし | 軽い |

段階5で adb から手作業で測った値（Duolingo が見えている間は 1 コア換算で約29%）と合う。

## 4. 透明性のページ（モニターの「Bento」タブ）

- 通信: INTERNET 権限の有無（実行時にパッケージ情報から確認）と、端末の起動後に Bento の uid が送受信したバイト数。実機では受信 0 B・送信 0 B。
- 権限: 要求している権限をすべて、許可の状態と用途付きで並べる。通知へのアクセスも含める。
- 保存しているデータ: 配置の件数、データベース・設定・キャッシュの大きさ。通知の内容とグラフの値は保存しないことを明記する。
- 自身の負荷: 起動後の CPU 時間、メモリ（PSS）、ホームを表示していた間の平均 CPU と描画数。

## 5. 負荷（実機）

| 状態 | 計測用プロセス | 本体 |
|---|---|---|
| モニター表示中・デバッグ版（最適化前） | 1コアの約12% | — |
| モニター表示中・デバッグ版（最適化後） | 約6% | 約6.5% |
| モニター表示中・リリース版 | 約5%（大半はファイルを開くカーネル側の処理） | 約3% |

最適化は、`/proc/<pid>/stat` を文字列に分割せずバイト列から直接数値を拾う、uid とプロセス名を pid と開始時刻で覚えておく、の2点。計測用プロセスは再起動まで動き続けるが、モニターを閉じている間は呼ばれないので CPU を使わない（実機で 30秒間 0 tick）。

### 安全のための制限

- 計測用プロセスはシェル権限でコマンドを実行できるので、Bento の uid 以外からの呼び出しは `onTransact` で拒否する。
- 受け取り口の ContentProvider は、一般のアプリが持てない INTERACT_ACROSS_USERS_FULL を要求し、さらに呼び出し元の uid がシェル（2000）か root（0）であることを確かめる。偽の窓口を渡されることを防ぐ。

## 7. 気づいた点

- 計測用プロセスの起動を一時的に Shizuku（外部アプリ）で行ったが、外部アプリは使わない方針のため、Shizuku は端末から削除し、ライブラリもコードから外した。起動部分は Bento 自身で用意する（`docs/operations.md`）。
- Shizuku では、計測用プロセスの版を変えずに中身だけ更新すると古いプロセスが使い回された。自前の起動では、APK が消えたら終了し、新しく起動したら古いほうを終了させるので起きない。
- プロセス名は起動時に `<パッケージ名>:monitor` に付け替える（`Process.setArgV0`）。付け替えないと一覧に「app_process」と出る。
- Bento を入れ直すと既定のホームが外れ、ホームの選択画面が出ることがある。
