## 1. フォルダー

### 使い方

- アプリを、ホームの別のアプリの上に重ねて離すとフォルダーになる。フォルダーの上に離すと中に足す。ホーム・ドック・アプリ一覧・別のフォルダーのどこから運んでも同じ。
- 重ねる判定は、指が相手の項目の中ほど（端から2割を除いた範囲）にあるときだけ。端の近くは普通の移動として扱い、隣に並べて置けるようにする。置き先の枠は、まとめるときは相手の項目の範囲に出る。
- タップで画面の中央に開く。外側のタップか戻る操作で閉じる。
- 名前は、開いたフォルダーの名前をタップして変える。開いたときは名前全体を選んだ状態にし、確定キーを押さずに閉じても入力した名前を残す。空にすると「フォルダー」に戻る。
- 中のアプリ: タップで起動、長押しでメニュー（ショートカット・アプリ情報・アンインストール・外観の個別設定・フォルダーから出す）、長押しのまま動かすとホームやドックへ運べる。運んでいる間はフォルダーを透明にして、指の操作が途切れないよう残す。
- ホームのフォルダーを長押しすると「開く」「名前を変更」「ホームから削除（中のアプリも）」。
- 中が1つになったらアプリに戻し、空になったら消す。アンインストールしたアプリは中からも外す（停止中に消えたアプリも起動時に外す）。
- バッジは中のアプリをまとめる。件数があれば合計、点だけなら点。
- 配置ロック中は、開いて起動することと名前の変更だけできる。
- すべての配置の変更は、これまでどおりスナックバーの「元に戻す」で取り消せる。

### 決めたこと

- フォルダーの中にフォルダーは入れない。フォルダーはドックに置けない（ドックはアプリだけを持つ）。
- 同じアプリを2回入れない。
- 見た目は角丸の半透明の下地に、先頭4つのアプリを小さく並べる。開いた画面は1行4つ。

### 構成

| 部品 | 内容 |
|---|---|
| `ItemContent.Folder` | 名前と中のアプリの並び |
| `LayoutEngine` | `mergeInto`・`removeFromFolder`・`renameFolder`・`removeApps`・`normalizeFolders`（単体テスト `FolderTest`） |
| `DragSource.FolderApp`・`DropTarget.Merge` | フォルダーから運ぶ、重ねてまとめる |
| `HomeController.mergeTarget` | 指の位置から、まとめ先を決める |
| `FolderUi.kt` | フォルダーのアイコン、ホームのフォルダー、開いたフォルダー |
| Room v4 | `workspace_item.title` と `folder_app`。v3 から自動マイグレーション |
| バックアップ v2 | `BackupItem` に `title`・`apps`。この端末に無いアプリは除き、1つ以下になったらアプリに戻す |

## 2. ホーム画面に追加

### 使い方

- Chrome の「ホーム画面に追加」→「ショートカットを作成」など、他のアプリがショートカットやウィジェットの追加を頼むと、Bento の確認画面が呼び出し元の上に出る。「追加」でホームの空いている場所（表示中のページから探す）に置く。
- 置いたショートカットは、タップで開き、長押しで「提供元のアプリ情報」「ホームから削除」、長押しのまま動かすと移動。
- 提供元がショートカットを消した・無効にしたときは「?」で表示し、タップすると理由を出す。
- フォルダーとドックには入れない（どちらもアプリだけを持つ）。

### 決めたこと

- 確認画面は独立した作業グループで開く（`taskAffinity=""`）。ホームの作業グループに入れると、背後に前のホーム（Pixel Launcher）が透けた。
- 受け入れた項目はチャンネルで渡し、ホームが配置を読み込んでから置く。
- ホームから外したショートカットは、取り消しの猶予が過ぎてから（次の配置の変更のとき）OS 側の固定も外す。すぐ外すと、提供元によっては OS がショートカットを消し、取り消しても戻らないため。プロセスが途中で終わった場合に備え、起動時に OS 側の固定と配置を突き合わせて、配置に無いものを外す。
- ウィジェットの追加依頼は、ID を割り当てて許可を得てから提供元に渡す（許可が要るときはウィジェットの追加と同じ画面を出す）。
- バックアップ v3 でショートカットを書く。読み込むと提供元が入っていれば戻す（開けるかは提供元が持っているか次第）。
- Room v5 で `workspace_item.shortcutId` を足した。

### 実機の確認

| 項目 | 結果 |
|---|---|
| Chrome の「ショートカットを作成」→ Bento の確認画面 | 合格。Chrome の上に出る |
| 「追加」でホームに置く | 合格。Chrome に戻り、ホームの空いている場所に置かれる |
| タップで開く | 合格。Chrome でそのページが開く |
| ホームから削除したときの OS 側の固定 | 合格。次の配置の変更で外れる。プロセスが終わっていた場合も起動時に外れる（`dumpsys shortcut` で確認） |
| ウィジェットの追加依頼 | 未確認（依頼を出すアプリが手元に無い） |

確認のために置いたショートカットは削除し、OS 側の固定も外れたことを確かめた。

### 気づいた点

- 開発中に APK を入れ直すと（新しい画面を足したときなど）、ホームの役割は Bento のままなのに、ホームキーで「ホームアプリを選択」が出ることがあった。「Bento Home」と「常時」を選べば戻る。

## 3. アプリの非表示・名前の変更

### 使い方

- アプリを長押し →「外観の個別設定」で、表示名と「アプリ一覧に表示しない」を変える。
- 表示名はホーム・ドック・フォルダー・アプリ一覧のすべてで使う。空にするか「元の名前に戻す」で元の名前に戻る。名前は入力中ではなく、閉じるとき（または確定キー）に保存する。
- 非表示はアプリ一覧からだけ隠す。ホーム・ドック・フォルダーに置いたものはそのまま。一覧の一番下の「非表示のアプリ N個を表示」で、薄く表示して戻せる。
- 一覧の検索は、表示名・元の名前・パッケージ名のどれでも見つかる。非表示のアプリは、表示に切り替えているときだけ検索に出る。

### 構成

- `app_appearance` に `hidden`・`label` を足した（Room v6、自動マイグレーション）。バックアップ v4 で書く。
- `HomeViewModel.displayApps`・`displayByRef` が表示名を反映した一覧。`AppEntry.originalLabel` に元の名前を残す。
- システムモニターのアプリ一覧は、表示名ではなく元の名前を使う（端末の状態を見る画面なので）。

### 実機の確認

| 項目 | 結果 |
|---|---|
| 表示名の変更（ホームのラベル） | 合格 |
| 非表示にすると一覧から消え、件数が減る | 合格（176 → 175 件） |
| 「非表示のアプリを表示」で薄く表示 | 合格 |
| 元の名前で検索 | 合格（「Discord」で表示名「Disco」が見つかる） |
| 「元の名前に戻す」・非表示の解除 | 合格。確認後に元へ戻した |

## 4. 下スワイプで通知パネル

- ホームの背景（ページの範囲）を下にスワイプすると通知パネルを開く。上スワイプのアプリ一覧と同じ判定（64dp 以上）。アイコンの上から始めても背景のスワイプとして扱い、ウィジェットの上はウィジェットに任せる。
- 設定 → ホーム画面 →「背景を下にスワイプして通知を開く」でオフにできる（初期値はオン。バックアップにも含める）。読み上げ中は、ホームの操作に「通知を開く」を用意した。
- 公開の API が無いので、他のランチャーと同じく `StatusBarManager.expandNotificationsPanel` をリフレクションで呼ぶ。必要な `EXPAND_STATUS_BAR` は通常の権限（インストール時に許可され、透明性のページにも用途を書いた）。呼べなかったときは、計測用プロセスが動いていれば `cmd statusbar expand-notifications` で開く。
- 実機（Android 17）ではリフレクションで開けた。上スワイプのアプリ一覧も変わらず動く。

## 5. 仕切り

- ホームの背景を長押し →「仕切り」で、そのページの仕切りを選ぶ。なし・二段・松花堂・幕の内・日の丸・重箱の1段。選ぶとすぐ反映し、取り消せる。配置ロック中でも変えられる（項目の配置は変えないため）。
- 見た目だけで、アイコンやウィジェットは区画をまたいで置ける。タップも受けない。
- 区画はページに対する割合で持ち、マス目の線には合わせない。最初は小マスの線に合わせたが、4列を3等分する「重箱の1段」で真ん中だけ細くなったため。
- 線は白（半透明）の下に薄い黒を重ねた二重線、中はごく薄い白で塗る。白だけだと明るい壁紙で見えにくかった。
- Room v7 で `workspace_page.partition`、バックアップ v5 で `BackupPage.partition` を足した。
- 実機で6種類を表示し、本人の確認を得た。確認後、使ったページは「なし」に戻した。

## 6. 一覧からまとめてホームに追加

本人の案。ホームのページが多いと、一覧からつまんで運ぶ間にページ送り（端で0.6秒ずつ）を待つのが大変なため。

- ホームが2ページ以上のとき、一覧のアイコンを長押しすると、つままずに選択する。選択中はタップで足し引きする。1ページのときは今までどおりつまんで運ぶ。配置ロック中は選択にしない（今までどおりメニュー）。
- 下に「N個を選択中 ｜ キャンセル ｜（1個なら）その他 ｜ ホームに追加」を出す。「その他」で今までの長押しメニューを開く。戻る操作・一覧を閉じると選択を捨てる。
- 「ホームに追加」でホームの縮小表示を出す。各ページのアイコン・フォルダー・ショートカット・ウィジェット（名前入りの箱）・仕切りを小さく描き、最後に「新しいページ」を並べる。ページの縦横比はホームの配置の範囲に合わせる。
- ページを選ぶと、そのページの空きへ選んだ順に置き、入りきらない分は後ろのページ（無ければ新しいページ）へ置く。前のページには戻らない（`LayoutEngine.placeApps`、単体テスト `PlaceAppsTest`）。置いたページを表示し、取り消せる。
- 実機で、2個を選んで2ページ目に置く、「その他」、戻る操作での解除を確認した。確認後に元へ戻した。
- 縮小表示の背景は不透明にした。わずかに透けると後ろの一覧が見えて読みにくかった。

## 7. 段階的な灰色表示と、記録の無いアプリの区切り

### 段階的な灰色表示

- 使っていない日数が段階の日数を越えるたびに色を抜く。札や文字は付けない。段階は設定 →「薄くする段階」で「7・14・30日」「14・30・60日」（初期値）「30・60・90日」から選ぶ。
- 段階ごとの彩度・不透明度は 0.55・0.92 → 0.25・0.82 → 0・0.7。ラベルは変えない。
- 日数の数え方は今までと同じ（最後に Bento から開いてから。一度も開いていなければ観測を始めてから）。通常の色を維持・バッジあり・観測直後は対象外。
- 以前の「薄くするまでの日数」は読み替える（7日→7・14・30日、14日→14・30・60日、30日・60日→30・60・90日）。始まりの日数が近いものにした。設定していなかった場合は新しい初期値になる。
- バックアップ v6 で `grayStages` を書く（以前の版にも読めるよう `grayDays` に最初の日数を残す）。
- 実機の記録は観測を始めて1日ほどなので、薄くなるアプリはまだ無い。段階の判定は単体テストで確かめた。

### 記録の無いアプリの区切り

- 使用回数は Bento を入れてから、このランチャーで開いた分だけを数える（plan.md §4）。記録の無いアプリは「よく使う順」「最近開いた順」で同じ順位になるので、「まだ Bento から開いていないアプリ（名前順）」の見出しで区切って後ろにまとめる。集計から除外したアプリと、一覧を開いた後に入ったアプリもここに入る。名前順では区切らない。
- 並び順を切り替えたら一覧の先頭に戻す。戻さないと、一覧は上に見えていたアプリの位置を保とうとするので、切り替えた直後に区切りより前が画面の外に隠れた（実機で気づいて直した）。

## 8. 棚卸しの一覧

- システムモニターの「棚卸し」タブ。設定の「アプリの棚卸し」からも開ける。ホームには出さない。
- 対象は起動できるアプリ（パッケージ単位）。システムのアプリは切り替えで表示する（アンインストールできないため）。
- 並べ替え: 使っていない順（初期）・容量・通信量・裏の通信量・電池。行をタップすると詳細を出し、「アンインストール」（OS の確認画面）と「アプリ情報」へ進める。アンインストールした行はすぐ消える。

| 値 | 出どころ | 条件 |
|---|---|---|
| 最後に使った | OS の使用記録（過去1年、`lastTimeVisible`・`lastTimeUsed` の新しいほう）。通知から開いた分なども含む | 使用状況へのアクセス |
| Bento から最後に開いた | Bento の記録（詳細だけ） | なし |
| 容量 | `StorageStatsManager`（本体・データ・キャッシュ） | 使用状況へのアクセス |
| 通信量・うち裏 | `NetworkStatsManager.querySummary`（直近30日、Wi-Fi とモバイル）。裏は `STATE_DEFAULT`（画面に出ていないとき） | 使用状況へのアクセス |
| 電池・うち裏 | `dumpsys batterystats` の「Estimated power use」の `UID` 行（前回のフル充電から）。裏は合計から前面（fg）を引いた分 | 計測用プロセス |
| カメラ・マイク・位置情報 | `dumpsys appops` の `Access:` の最新時刻（位置は細かい・おおまかの新しいほう） | 計測用プロセス |

- `dumpsys appops` は全体で約2MB・6万行あり、計測用プロセスから Bento へそのまま渡すとプロセス間通信の上限を超えるおそれがある。計測用プロセス側で awk を使い、必要な行だけ（約46KB）にしてから渡す。`dumpsys batterystats` も `UID` 行だけ（約10KB）にする。どちらも1〜2秒。
- 読み込みはタブを開いたときと「読み直す」のときだけ。数秒かかる。
- Bento 自身の電池は、起動用の入口の名前で「Bento Home 設定」として並ぶ（ホームと設定は同じ uid）。
- 実機で、使っていない順・電池・裏の通信量の並べ替え、詳細（カメラ・マイク・位置を含む）を確認した。アンインストールは押していない。
- 表示の調整: 記録の無いときは「記録なし」とだけ出す（期間は一覧の上に書く）。0.05mAh 未満の電池は説明に出さない。

## 9. 使ってみての手直し（2026-10-27）

| 気になった点 | 直したこと |
|---|---|
| 一覧の選択中のバーで、1個のときだけ「その他」が出て「1個を選択中」が折り返す | 2段にした。上に件数・キャンセル・その他（常に同じ位置、2個以上なら押せない表示）、下に画面幅の大きな「ホームに追加（N個）」 |
| アプリ一覧の開閉にアニメーションが無い | 下からせり上がって開き、下へ戻って閉じる（220ms、画面の1/3の距離＋フェード） |
| ホームのアイコンを長押しすると、つまむ状態とメニューが同時に出る | 長押しが成立したら振動して「つまめる状態」にするだけにし、動かさずに離したときにメニューを出す。ウィジェットも同じ |
| つまむと壁紙がずれる | ドラッグ中は置き先として末尾に空のページを足すため、ページ数が変わって壁紙の位置が動いていた。壁紙の位置は実際のページ数で計算する。壁紙の画像は OS の設定のもので、Bento は位置を伝えるだけ |
| 移動するときの目安が無い | つまんでいる間だけ、マス目の薄い線と半マスの点を出す |

- 実機で、長押しして離すとメニュー、つまんで動かすとガイドが出て壁紙は動かない、を確認した。確認で動かした Discord は元の位置に戻した。
- 確認の途中、`input motionevent` で背景のメニューを開いたまま操作して、誤って「配置をロック」を押していた（ドラッグが始まらない原因を調べて気づいた）。ロックは解除した。`input motionevent` は1回ごとに別の操作として扱われるため、長押しやドラッグの確認には `input swipe`（同じ点）と `input draganddrop` を使う。

## 10. ウィジェットのサイズ・ページの整理・ループ（2026-10-27）

### ウィジェットのサイズ

- Duolingo（`StreakWidgetProvider`・`MediumStreakWidgetProvider`）は提供元が `resizeMode=0`（サイズ変更不可）を指定している。他のランチャーでも変えられない。
- GitHub（`ContributionGlanceWidgetReceiver`）は `resizeMode=3` だが、高さの最大が1マス（小マス2）で、横幅だけ2〜4マスで変えられる。縦のつまみを引いても変わらなかったのはこのため。実機で横幅の変更を確かめ、元の幅に戻した。
- 変えられることが画面から分からなかったので、最小と最大が同じ方向のつまみは出さない。どの方向も変えられないウィジェットは、メニューに「サイズは変えられません（提供元の指定）」を押せない状態で出す。

### ページの整理

- 背景の長押し →「ページの整理」（2ページ以上のとき）。縮小したページを並べ、◀▶で順番を入れ替える。空のページは「空のページを削除」で消せる（最後の1ページは消さない）。どれも取り消せる（`LayoutEngine.movePage`・`removeEmptyPage`、単体テスト `PageOrderTest`）。
- 下に出る「元に戻す」のお知らせが最後の行のボタンを隠したので、一覧の下に余白を空けた。
- 実機で並べ替えて元の順番に戻した。

### ページのループ

- 設定 → ホーム画面 →「ページをループする（最後の次を最初に）」。初期値はオフ。バックアップにも含める。
- 最後のページでさらに左へ（160px 以上）めくると最初のページへ、最初のページで右へめくると最後のページへ移る。ウィジェットの上の横ドラッグでも同じ。アイコンを運んでいる間はループしない（末尾に置き先の新しいページを出すため）。
- 指を離した直後はページャー自身の寄せる動きが走ってこちらの移動を打ち消したので、その動きが終わってから移す。
- 実機で両方向を確かめ、設定はオフに戻した。
